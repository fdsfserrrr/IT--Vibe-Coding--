# IT爱学堂-Vibe Coding全栈开发实战课(完结)

意图工程与规格驱动——Vibe Coding 的技术起点
Vibe Coding 由 Andrej Karpathy 于 2025 年提出，核心定义是开发者通过自然语言表达编程意图，由 AI 模型完成代码生成、调试和优化，人的工作重心从“如何写代码”转向“描述要什么”和“验证结果是否正确”。但这并不意味着随意说几句话就能得到可用的产品，Vibe Coding 的技术起点是一套严格的意图定义与规格驱动方法。

为什么“随口说”一定会翻车
当前 AI 辅助编程模式的根本问题在于，开发过程高度依赖于操作者的个人能力。用户需要通过提示词引导模型，不断提醒模型不要偏离方向，并对模型生成的代码进行细致的审查和调试。这个过程不仅效率低下，而且极度依赖个人经验，难以规模化。更严重的是，AI 编程存在不可复现性——同样的提示，两次生成的代码可能截然不同；AI 为了“完成任务”会做出大量用户看不到的隐性假设，这些假设在简单场景下无伤大雅，但在复杂业务逻辑中就是定时炸弹。

Vibe Coding 的技术解决路径不是“更聪明的提示”，而是将传统软件工程中被验证行之有效的实践——需求分析、系统设计、任务分解——压缩并作为 AI 生成代码的强制前置步骤。

Spec-Driven Development 的技术定位
Spec-Driven Development（SDD）的核心理念是将“规格”作为软件开发的第一性产物，以规范驱动设计、实现、验证与演进。GitHub 推出的 Spec Kit 被描述为“一个开源工具包，让你专注于产品场景和可预测的结果，而不是从头对每一块进行 Vibe Coding”。Spec Kit 与 30 多个 AI 编码智能体兼容，其核心机制是在 AI 真正动手写代码之前，先产出一系列可版本控制的工程产物。

SDD 的结构化工作流包含五个阶段：Specify（撰写规格）→ Plan（制定计划）→ Tasks（任务分解）→ Implement（实现）→ Converge（收敛验证）。在 Specify 阶段，开发者输入的模糊提示被 AI 转化为一份结构化的需求文档，包含明确的验收标准。在 Plan 阶段，需求被翻译为可执行的设计方案。Tasks 阶段则将设计拆解为可并行执行的原子任务。SDD 并不是 Vibe Coding 的对立面，而是它的进化——Vibe Coding 负责快速探索和原型验证，SDD 负责将探索结果固化为可复现的工程产出。

意图工程的技术内涵
IEEE/ACM 发表的 Vibe Engineering 论文提出 Intent Engineering 作为 Vibe Coding 的两大技术支柱之一。Intent Engineering 的核心是“通过多智能体对话、心智理论原则和测试驱动需求精炼来深入理解用户需求，而非表面陈述”。这意味着意图工程不是简单地“把需求写清楚”，而是建立一套从模糊期望到可验证规格的技术转换机制。

在实际操作中，意图工程要求开发者区分三个层次：高层意图（产品目标和用户价值）、架构约束（技术栈、安全规则、性能要求）以及验收标准（功能行为、边界条件、异常路径）。Vibe Coding 全栈开发中，开发者输出的不是详细 PRD，而是“高层意图 + 边界约束”，这一步是 Vibe Coding 成败的关键。规格文档是人与 AI 之间的契约，也是项目可持续迭代的基础。技术吃透 Vibe Coding 的标志，不是能写出漂亮的提示词，而是能设计出让 AI 可稳定执行的规格体系。
